# xtask

`src/main.rs` starts the runtime and invokes the CLI. `src/cli.rs` owns top-level
parsing and dispatch. Each command has a directory under `src/commands/`:

- `check_rust_stable/`: `mod.rs` owns arguments and orchestration; `channel.rs`
  fetches channel manifests, `versions.rs` parses and scans Rust versions,
  `github.rs` manages sync issues, and `report.rs` formats output.
- `check_skill_snippets/`: `mod.rs` owns arguments and orchestration;
  `discovery.rs` finds Rust fences, `runner.rs` generates and executes one
  Rustdoc crate per skill, and `setups/` supplies per-skill dependencies.

Unit tests live with the code they cover. `tests/check_rust_stable.rs` exercises
the Rust-stable command through the binary and a local HTTP server.
`tests/check_skill_snippets.rs` checks snippet selection and rejection through
the binary; the snippet CI job also compiles and runs the accepted examples.
`cargo machete` checks dependencies of the Rust maintenance workspace.

## Skill snippet checks

Run `just check-skill-snippets` (or
`cargo xtask check-skill-snippets`) to discover Rust code fences in every
Markdown file under `skills/`, lint them with the workspace policy, and execute
their tests with Cargo. New Rust examples are included automatically. Generated
target names identify the source document, and nested module names identify the
fence's opening line.

Each skill with Rust examples has a setup in
`src/commands/check_skill_snippets/setups/<skill>.toml` that declares its Rust
version and dependencies. The runner writes one crate for that skill under
`target/skill-snippets/<skill>/` and one integration-test target per Markdown
document. Fences are nested in source order so later examples can use definitions
from earlier examples while local redefinitions remain isolated. Statement
examples become generated tests; existing `#[test]` functions, including tests
generated by `rstest`, run through Cargo's native test harness.

The runner formats generated source, runs Clippy with the workspace lint tables
and `-D warnings`, executes integration tests, and delegates special rustdoc
semantics such as `compile_fail` to `cargo test --doc`. Cargo build output is
shared under `target/skill-snippets/build`. Dependency resolution may access the
registry. Generated manifests, lockfiles, and Rust source stay under `target/`;
the workspace lockfile and skill directories stay unchanged. The runner disables
automatic inline snapshot acceptance.

Use these options for focused work:

```sh
just check-skill-snippets --list
just check-skill-snippets --filter type-state-pattern
just check-skill-snippets --skills-root /path/to/skills
cargo xtask check-skill-snippets --deny-ignored
```

`--list` reports discovery only. `--filter` selects Markdown paths by substring.
The selected paths choose the per-skill crate; that crate validates every Rust
fence from the selected skill. An empty selection fails. The `just` recipe and CI
pass `--deny-ignored`; direct CLI callers can use the same flag.

Rust fences use these attributes:

- `rust`: lint and compile items, execute statements, and run contained tests.
- `rust,no_run`: lint and compile the example without executing contained tests.
- `rust,compile_fail`: require compilation to fail for intentionally invalid Rust.
- `rust,should_panic`: require the example to panic through rustdoc.
- `rust,ignore (reason)`: identify an explicit exclusion for discovery; strict
  repository checks reject it. Use hidden setup lines or a non-Rust fence for
  context-only outlines.

Edition attributes and `standalone_crate` retain rustdoc semantics. The runner
rejects unknown Rust fence attributes. Parenthesized comments may appear between
attributes; attributes after a comment are still checked. Comments must be
closed and non-nested. Keep support code in hidden `#` lines when it would
distract from the example.

The check covers explicitly tagged Rust fences, including backtick and tilde
fences in Markdown lists and blockquotes. It excludes other languages, untagged
fences, inline code, and Rust fences shown inside outer
Markdown examples. The reported count is Rust snippet
coverage, not a claim that shell commands, template fragments, or agent
behavior were validated. A function definition that compiles is only exercised when the
snippet calls it.
